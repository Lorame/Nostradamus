# Nostradamus — UEFA Data Collection Journey

## Research and Data Collection Session

**Date:** 22 August 2026

---

# 1. Objective of the session

The objective of this work session was to build the first reliable data foundation for the Nostradamus football prediction engine.

The project requires structured information about European football clubs in order to simulate and predict competition structures, especially for the UEFA Champions League.

The required data included:

- Club names
- Countries
- UEFA identifiers
- Official UEFA URLs
- UEFA coefficients
- Historical European performance data
- Information required for future draw constraints

The main challenge was finding a reliable and reproducible data source.

---

# 2. Searching for reliable data sources

The first step was identifying possible sources for UEFA club information.

Several approaches were explored:

- Official UEFA website
- Third-party ranking websites
- Open databases
- Search engines
- External football datasets

The priority was always to use official sources whenever possible.

---

# 3. Exploration of third-party sources

## Kassiesa

A first approach explored UEFA coefficient data available through Kassiesa.

The objective was to retrieve:

- European club rankings
- Historical coefficients
- Club information

This source contained interesting information, but a problem appeared when trying to match clubs automatically with UEFA data.

---

## Fuzzy matching tests

Automatic matching was tested using:

- Name normalization
- Fuzzy matching algorithms
- RapidFuzz similarity scores

The goal was to connect club names from external sources with official UEFA entities.

The approach worked for many clubs, but several incorrect matches appeared.

Examples of issues:

- Similar club names producing false positives
- Small clubs incorrectly matched with famous teams
- Ambiguous names creating unreliable links

Because of these limitations, fuzzy matching was not considered reliable enough as the main identification method.

---

# 4. Wikidata exploration

Another approach was testing Wikidata as a source of structured identifiers.

The objective was to use Wikidata to connect:

- Club names
- External identifiers
- Countries
- Official references

Results:

- Many clubs were successfully matched automatically.
- Some clubs required manual validation.
- Some cases remained ambiguous.

Although useful as a complementary source, Wikidata alone was not sufficient for the main dataset.

---

# 5. Searching UEFA URLs automatically

The next objective was finding official UEFA URLs for clubs.

Several search-based approaches were considered.

The idea was:

1. Search for a club name.
2. Retrieve the UEFA page.
3. Extract the UEFA club identifier.

---

# 6. Search engine experiments

## Google Custom Search

Google Custom Search was considered for automated URL discovery.

However, limitations appeared:

- API restrictions
- Limited free usage
- Not suitable for hundreds of clubs

The approach was abandoned.

---

## DuckDuckGo

DuckDuckGo was tested as an alternative.

The objective was to automatically find UEFA pages by searching:

```
club name + UEFA
```

The results were promising for some clubs.

The extraction strategy was based on:

- Searching only UEFA domains
- Extracting club identifiers from URLs
- Validating the final URL

This approach was useful for exploration but was not needed after discovering the official UEFA API.

---

# 7. Direct UEFA website scraping attempts

The first official UEFA approach was based on scraping the website directly.

Technologies tested:

- BeautifulSoup
- Playwright

The scraper successfully extracted some information:

- Club names
- Countries
- UEFA URLs

However, an important limitation appeared.

Only a small number of clubs were visible.

The page initially displayed approximately 10 clubs instead of the complete ranking.

---

# 8. Problems with dynamic loading

Several solutions were tested:

- Clicking "More" buttons
- Triggering JavaScript loading
- Inspecting the DOM
- Using Playwright interactions

The problems were caused by:

- Dynamic frontend rendering
- JavaScript-generated content
- Hidden pagination mechanisms

The HTML page was only a presentation layer and did not contain the complete dataset.

The scraping approach was therefore abandoned.

---

# 9. Network analysis and API discovery

A new strategy was used:

Instead of scraping the webpage, the network requests generated by UEFA were analyzed.

Tools used:

- Playwright network interception
- JSON extraction
- Manual JSON inspection

Several JSON endpoints were discovered:

- Vocabulary endpoints
- Live score endpoints
- Tracking-related resources

Eventually, the official UEFA coefficient API was identified:

```
https://comp.uefa.com/v2/coefficients
```

---

# 10. UEFA API extraction

The UEFA API provided exactly the required information.

The response contained:

- Club identity
- UEFA ID
- Country
- Current coefficient
- Historical seasonal coefficients

The JSON structure required some investigation.

The useful information was located inside:

```
data
 └── data
      └── members
```

Each member contained:

```
member
overallRanking
seasonRankings
```

After understanding the structure, the extraction script was rewritten.

---

# 11. Pagination handling

The API returned results by pages.

The extraction process was updated to iterate through all pages:

```
page=1
page=2
page=3
...
page=9
```

with:

```
pagesize=50
```

This allowed the retrieval of the complete ranking.

---

# 12. Final successful extraction

The final extraction successfully retrieved:

```
415 clubs
```

The generated dataset:

```
data/raw/uefa_club_coefficients_full.csv
```

contains:

- UEFA club IDs
- Club names
- Official names
- Countries
- Current UEFA coefficient
- Five previous seasons of coefficients

---

# 15. Lessons learned

## Official APIs are often better than web scraping

A modern website is often only a frontend interface.

The real data may come from:

- internal APIs
- JSON endpoints
- backend services

Finding the data source is often more efficient than scraping the visible page.

---

## Data engineering is an iterative process

The final solution was not obtained immediately.

The workflow was:

1. Search for possible sources.
2. Test different approaches.
3. Identify limitations.
4. Investigate alternative solutions.
5. Discover the official API.
6. Build a reliable extraction pipeline.

Each failed attempt provided information that helped reach the final solution.

---

# Conclusion

This session transformed an initial scraping problem into a complete UEFA data extraction pipeline.

The first major football dataset for Nostradamus has now been created.

The next step will be combining this UEFA coefficient dataset with the Champions League 2026/2027 participant list to create the first complete input dataset for the prediction engine.
